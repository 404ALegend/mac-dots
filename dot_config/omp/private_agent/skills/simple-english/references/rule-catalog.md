# Rule catalog: ASD-STE100 Issue 9 for software text

Read this file for CHECK mode, Strict mode, or a rule number. It paraphrases the 53 rules of Issue 9 with software guidance. The official wording is available at asd-ste100.org.

## Section 1: Words (Rules 1.1-1.14)

| Rule | Instruction |
|---|---|
| 1.1-1.4, 1.6 (Strict) | Use only approved words, in their approved part of speech, meaning, and form. |
| 1.5 | Technical nouns are legal. |
| 1.7 | Do not use technical nouns as verbs. |
| 1.8-1.10 | Use short, clear technical nouns from the project or industry. Do not use regional, slang, or jargon nouns. |
| 1.11 | Give each item one name. |
| 1.12 | Technical verbs are legal. Prefer a common verb when it means the same. |
| 1.13 | Do not use technical verbs as nouns. |
| 1.14 | Use American spelling. |

Plain mode permits project vocabulary under rules 1.5, 1.8, and 1.12.

## Section 2: Multi-word nouns (Rules 2.1-2.2)

| Rule | Instruction |
|---|---|
| 2.1 | Use multi-word nouns of three words or fewer. |
| 2.2 | Write a longer technical noun in full once, then give a short form or hyphenate its units. |

Break noun chains with prepositions: "the timeout value for the connection pool."

## Section 3: Verbs (Rules 3.1-3.7)

| Rule | Instruction |
|---|---|
| 3.1 (Strict) | Use only dictionary verb forms. |
| 3.2-3.4 | Use simple forms and tenses. Do not use present perfect or complex auxiliaries. |
| 3.5 | Use an "-ing" form only as a technical noun or inside one. |
| 3.6 | Use active voice. Passive voice is legal only when the actor is unknown. |
| 3.7 | Describe an action with a verb, not an action noun. |

Use only can, will, and must as modals. See the modal ladder below.

## Section 4: Sentences (Rules 4.1-4.5)

| Rule | Instruction |
|---|---|
| 4.1 | Write short, clear sentences. |
| 4.2 | Do not omit words or use contractions. |
| 4.3 | Use a vertical list for complex text. |
| 4.4 | Use connecting words between related sentences. |
| 4.5 | Put an article or demonstrative adjective before applicable nouns. |

## Section 5: Procedural writing (Rules 5.1-5.5)

| Rule | Instruction |
|---|---|
| 5.1 | Maximum 20 words per sentence. |
| 5.2 | One instruction per sentence, except simultaneous actions. |
| 5.3 | Use the imperative. |
| 5.4 | Put each required condition before the command. |
| 5.5 | Notes give information, never instructions or limits. |

## Section 6: Descriptive writing (Rules 6.1-6.6)

| Rule | Instruction |
|---|---|
| 6.1 | Give one new fact per sentence. |
| 6.2 | Use key words and phrases for structure. |
| 6.3 | Maximum 25 words per sentence. |
| 6.4-6.5 | Group related information by one topic per paragraph. |
| 6.6 | Maximum six sentences per paragraph. |

## Section 7: Safety instructions (Rules 7.1-7.3)

| Rule | Instruction |
|---|---|
| 7.1 | Name the risk level: WARNING for injury and CAUTION for damage. |
| 7.2 | Start with a clear command or condition. |
| 7.3 | Then give the risk or result. |

## Section 8: Punctuation and word count (Rules 8.1-8.7)

| Rule | Instruction |
|---|---|
| 8.1 | Use standard punctuation except semicolons. |
| 8.2 | Hyphenate words that act as one unit. |
| 8.3 | Parentheses are legal for references, abbreviations, explanations, and alternatives. |
| 8.4 | Each vertical-list item has its own word budget. |
| 8.5-8.7 | Count parenthetical text, hyphenated words, numbers, identifiers, and quoted text as one word each. |

Do not use em dashes to splice statements. Name the relation or write two sentences.

## Section 9: Writing practices (Rules 9.1-9.4, GR-1 to GR-8)

| Rule | Instruction |
|---|---|
| 9.1 | Restructure when a word-for-word replacement does not work. |
| 9.2 (Strict) | Use each approved word in its approved meaning and part of speech. |
| 9.3 | Prefer a one-word verb to a phrasal verb. |
| 9.4 | Keep terminology and style consistent. |

Keep "that", put the primary verb first, make pronouns clear, write "this" with its noun, and use inclusive language. Replace "e.g." with "for example", "i.e." with "that is", and name items instead of using "etc.".

## The modal ladder

| You wrote | Write instead |
|---|---|
| should (requirement) | must |
| should (recommendation) | Delete it, or state it as fact. |
| should (inverted conditional) | if |
| may, might, could | can |
| would | can, or restructure as a condition and result. |

## Signs of AI writing

Delete inflated significance, negative parallelism, decorative triplets, vague attribution, false ranges, restating summaries, editorializing asides, and decorative formatting. State measurable facts instead.

## Word choice

Use one word with one meaning and one part of speech through the document. Use `configuration`, not a mix of config, settings, and options. Use `make sure that`, not a mix of check, verify, confirm, validate, and ensure.
